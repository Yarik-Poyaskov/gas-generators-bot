# ⚡ GPU Checklist Bot & Energy Portal

Комплексна система корпоративного рівня для автоматизації збору, верифікації та моніторингу даних газопоршневих установок (ГПУ). Проєкт поєднує в собі Telegram-бота для збору оперативної звітності на базі Finite State Machine (FSM) та сучасний веб-інтерфейс (Next.js 16 / Tailwind CSS 4) для візуалізації статусу об'єктів у реальному часі.

---

## 🚀 Основний функціонал

### 🤖 Telegram Бот (`@gpu_checklist_bot`)
*   **Автоматична кольорова класифікація (Кола, Квадрати, Трикутник)**: Миттєва фонова класифікація кожного звіту на основі графіків трейдерів, попереднього стану ГПУ та виявлених дефектів без додаткових дій з боку оператора.
*   **Запобігання небалансам та розумна маршрутизація**: Автоматична фільтрація звітів для групи трейдерів (`SPECIAL_GROUP_ID`) та сповіщення моніторингової групи «Увага! Увага!! Увага!!!» (`ATTENTION_GROUP_ID`) з попередженням про ризик формування небалансів.
*   **Швидкі статуси мережі (в 1 клік)**: Кнопки `⚡️ Пропала мережа` та `💡 З'явилась мережа` для миттєвої фіксації аварій живлення із синхронною розсилкою у групу об'єкта та групу «Увага!».
*   **Повний чек-лист (15 пунктів)**: Покроковий процес введення параметрів із суворою числовою валідацією, підтримкою нульових значень та авто-перевіркою порогів.
*   **Контроль температури рідини Т206 / Т207**: Почерговий контроль температур охолодження двигуна з автоматичним формуванням попередження при падінні температури $\le 39^\circ\text{C}$.
*   **Сервісне сповіщення ТО (🔵)**: Автоматичні алерти про наближення регламентного ТО (відбір/заміна оливи, змащування підшипників генератора при залишку $\le 24$ м/год).
*   **Гнучкі режими роботи**: Вибір режиму ("Острів", "Мережа", "Не працює, готова до пуску", "ГПУ в аварії, не готова до пуску."). При зупиненій установці доступна кнопка **"⏩ Пропустити"** для неактивних параметрів.
*   **Розумна обробка тиску**: Розділений запуск та фіксація тиску для 4-х контурів охолодження (малий та великий контури, до та після запуску ГПУ).
*   **Фото-фіксація**: Обов'язкове завантаження фотографій мультиметра та ЩОС для підтвердження внесених даних.
*   **Керування змінами (Shifts)**: Логіка заступання та здачі зміни операторами з відображенням реального ПІБ, автоматичними нагадуваннями про завершення зміни та автозакриттям після налаштованого інтервалу.
*   **Система Опитувань (Survey 1)**: Збір фото та коментарів безпосередньо в групах об'єктів з блокуванням опитування першим відповілим та вивантаженням результатів у Google Sheets.
*   **Таргетована розсилка (Broadcast)**: Створення розсилок в адмін-панелі з вибором конкретних груп об'єктів, можливістю прикріплювати будь-які документи (PDF, Word, Excel) нарівні з зображеннями та предпросмотром перед надсиланням.
*   **Адміністрування безпосередньо з бота**: Інлайн-меню для редагування параметрів звітів, коригування значень, налаштування розкладу надсилання звітів та інтервалів перевірок.

### 🌐 Energy Portal (Web Dashboard)
*   **Live Status**: Моніторинг усіх ГПУ на одній сторінці з миттєвим оновленням через WebSockets.
*   **Автонаслідування статусів ГПУ**: Автоматична передача останнього статусу, режиму роботи, автора та потужності зі вчорашнього дня на сьогодні для безперервного графіка роботи на стыку суток (24:00 -> 00:00), якщо звіт ще не заповнено оператором.
*   **Редизайн індикаторів**: Стильні градієнтні кольори смуги потужності (синій градієнт за звичайних умов, оранжево-червоний при критичному навантаженні >90%) зі збільшеною товщиною для покращеної читаності.
*   **PWA (Progressive Web App)**: Можливість встановлення сайту як додатка на смартфон із власними синьо-жовтими градієнтними іконками та фоновим кэшуванням ресурсів за стратегією *Stale-While-Revalidate* через Service Worker.
*   **Web Push Сповіщення**: Сповіщення в реальному часі про аварії ГПУ на підключених пристроях.
*   **Портал Трейдера**: Веб-інтерфейс для публікації графіків роботи, імпорту розкладів та парсингу повідомлень з Telegram з покращеною фільтрацією стопів (виключення помилкових спрацювань на дефісах у назвах об'єктів типу `KC GPU-1`).
*   **Історія та аналітика**: Таблиця звітів з пагінацією, фільтрацією та можливістю експорту даних в Excel (`.xlsx`) безпосередньо з фронтенду через API.
*   **Безпека**: OTP авторизація через Telegram, JWT токени доступу, захист від дублювання розкладів (Trader Schedules).

## 📋 Покроковий чек-лист Telegram-бота (15 кроків)

При виборі опції **"Заповнити Чек-Лист"** бот послідовно проводить оператора через наступні кроки:

1.  **Режим роботи ГПУ**: Вибір із кнопок (`Острів`, `Мережа`, `Не працює, готова до пуску`, `ГПУ в аварії, не готова до пуску.`).
2.  **Час події (запуску / зупинки / поточний час)**: Інлайн-клавіатура для точного вибору години та хвилин.
3.  **Навантаження ГПУ**: Розділений ввід:
    *   *3.1 Потужність (%)* — числове значення (дозволено `0` / `0.0`).
    *   *3.2 Потужність (кВт)* — числове значення.
4.  **Статус роботи ГПУ**: Вибір із кнопок (`Стабільна`, `З аваріями`, `Не працює`).
5.  **Напруга АКБ стартера**:
    *   *5.1 Напруга АКБ 1 (В)* — числове значення.
    *   *5.2 Напруга АКБ 2 (В)* — числове значення (авто-перевірка порогу `< 27.0 В`).
6.  **Температура охолоджуючої рідини двигуна**:
    *   *6.1 Температура Т206 (°C)* — числове значення.
    *   *6.2 Температура Т207 (°C)* — числове значення (авто-попередження оператору та в групу при $\le 39^\circ\text{C}$).
7.  **Тиск малого контуру (інтеркулер)**:
    *   *7.1 До пуску ГПУ (GK/MCC, до насоса)* — тиск (бар, доступна кнопка `⏩ Пропустити`).
    *   *7.2 Після пуску ГПУ (GK/MCC, до насоса)* — тиск (бар, доступна кнопка `⏩ Пропустити`).
8.  **Тиск великого контуру (двигун)**:
    *   *8.1 До пуску ГПУ (NK/ECC, до насоса)* — тиск (бар, доступна кнопка `⏩ Пропустити`).
    *   *8.2 Після пуску ГПУ (NK/ECC, до насоса)* — тиск (бар, доступна кнопка `⏩ Пропустити`).
9.  **Напруга батареї Haas**: Напруга внутрішньої батареї контролера Haas (В).
10. **Генерація всього (МВт*год)**: Наростаючий підсумок виробітку електроенергії.
11. **Напрацювання (мотогодини)**: Поточні мотогодини роботи двигуна (г).
12. **Ліміт відбору оливи**: Мотогодини, що залишилися до відбору проби оливи на аналіз (г, авто-попередження 🔵 при $\le 24$ м/год).
13. **Ліміт змащування підшипника**: Мотогодини, що залишилися до змащення підшипника генератора (г, авто-попередження 🔵 при $\le 24$ м/год).
14. **Звірка комутаційних апаратів**: Підтвердження положення апаратів (ВК ГПУ, Т-1, Т-2, ВВ ГПУ, Ввод-1, Ввод-2, КЛ-1, КЛ-2, СВ-0,4 кВ).
15. **Фото-фіксація**: Послідовне завантаження фотографій мультиметра та ЩОС.

## 🎨 Візуальна класифікація статусів ГПУ та маршрутизація

Система підтримує інтелектуальну класифікацію статусів агрегатів у реальному часі без зміни інтерфейсу оператора:

### 🔵 Кола (Запуск ГПУ / Генерація)
* 🟢 **Зелене коло**: Плановий старт згідно графіка трейдера (відхилення $\le 5$ хв, режим відповідає плану, аварій немає).
* 🟡 **Жовте коло**: Несвоєчасний старт (запізнення $> 5$ хв від плану, пуск поза графіком або без графіка в ручному режимі).
* 🟠 **Помаранчеве коло**: Невідповідність режиму (час пуску співпав, але переплутано режим *Мережа*/*Острів*).
* 🟣 **Фіолетове коло**: Старт ГПУ після аварійної зупинки / простою (відновлення генерації).
* 🔴 **Червоне коло**: Запуск вчасно і на планову потужність, але з технічними зауваженнями/аваріями.
* 🔵 **Синє коло**: Регламентне ТО (сервісні сповіщення при залишку $\le 24$ м/год до відбору оливи або змащування підшипників).

### ⬛️ Квадрати (Зупинка ГПУ)
* 🟩 **Зелений квадрат**: Планова зупинка за графіком трейдера вчасно (відхилення $\le 5$ хв, без аварій).
* 🟨 **Жовтий квадрат**: Несвоєчасна зупинка / переробіток часу (запізнення із зупинкою $> 5$ хв від плану, перевиробіток зайвої е/е в мережу або зупинка поза графіком).
* 🟪 **Фіолетовий квадрат**: Зупинка з несправностями (машина допрацювала інтервал за графіком, але є дефекти; подальший пуск можливий, небалансів немає).
* 🟥 **Червоний квадрат**: Аварійна зупинка (експлуатація неможлива, машина не готова до пуску).

### 🔺 Трикутник (Робота / Чек-лист без зупинки)
* ⚠️ **Жовтий трикутник**: Попередження про дефект або несправність під час роботи чи огляду без зупинки установки.

| 🟣 | Старт після аварії | ✅ *(без ПІБ)* | ✅ *(з плашкою небалансу)* | ✅ | ✅ |
| 🔴 | Старт вчасно з аваріями | ✅ *(без ПІБ)* | ❌ | ✅ | ✅ |

| 🟪 | Зупинка з несправностями | ✅ *(без ПІБ)* | ❌ | ✅ | ✅ |

> `⚠️ Шановні трейдери, увага, внаслідок порушення робочого графіку можуть бути сформовані небаланси!`

## 🔧 Розгортання та Налаштування

### 1. Системні вимоги
*   Python 3.10+
*   Node.js 20+
*   Права локального адміністратора (опціонально, для точного логування та портів)

### 2. Налаштування середовища (`.env`)
Створіть файл `.env` у кореневій директорії проєкту за наступним зразком:

```env

GROUP_ID=-1001234567890                        # Основний чат для відправки звітів
SPECIAL_GROUP_ID=-1001234567890                 # Чат для звітів трейдерам (без ПІБ)

GOOGLE_SHEETS_JSON_KEY=service_account.json
GOOGLE_SHEETS_URL=https://docs.google.com/spreadsheets/d/your_spreadsheet_id/edit
GOOGLE_APPS_SCRIPT_URL=https://script.google.com/macros/s/your_script_id/exec
GOOGLE_APPS_SCRIPT_TOKEN=your_secret_upload_token
```

> [!WARNING]
> Переконайтеся, що `GOOGLE_SHEETS_JSON_KEY` вказує на коректний файл сервісного акаунта у корені проєкту, якщо увімкнено вивантаження звітів.

### 3. База даних та міграція

При першому запуску файл бази даних `reports.db` створюється автоматично. Проте, якщо схема бази даних зазнала змін, необхідно застосувати міграції:

```powershell
# Додавання нових полів чек-ліста (тиск та ліміти)
python migrate_add_new_fields.py

# Створення таблиці смен (shifts)
python migrate_shifts.py

# Налаштування інтервалів нагадувань смен
python migrate_shift_interval.py
```

> [!IMPORTANT]
> Якщо вам потрібно повністю очистити схему бази даних для запуску з нуля, просто видаліть файл `reports.db`:
> `Remove-Item -Path "reports.db" -ErrorAction SilentlyContinue` (PowerShell) або `del reports.db` (CMD).

### 4. Запуск бекенду (Бот + API Server)
Усі залежності встановлюються через `requirements.txt`. Бот та FastAPI сервер працюють в одному циклі подій, що забезпечує стабільну відправку WebSocket-повідомлень.

```bash
# Встановлення залежностей Python
pip install -r requirements.txt

# Запуск системи
python bot.py
```

### 5. Запуск фронтенду (Next.js Dashboard)
Створіть у папці `/frontend` файл `.env.local` з URL-адресою бекенду:
```env
NEXT_PUBLIC_API_URL=http://localhost:7895
NEXT_PUBLIC_WS_URL=ws://localhost:7895
```

Виконайте збірку та запуск:
```bash
cd frontend

# Встановлення NPM залежностей
npm install

# Запуск у режимі розробки
npm run dev

# Збірка продакшн-версії
npm run build
npm run start
```

## 📈 Google Apps Script (GAS) для вивантаження фотографій

Щоб обійти ліміт вільного дискового простору сервісних акаунтів Google (0 байт), завантаження фотографій реалізовано через персональний аккаунт за допомогою Google Apps Script. 

1. Створіть новий проект Google Apps Script у вашому Google Drive.
2. Вставте код скрипта, який приймає `POST` запити з токеном `GOOGLE_APPS_SCRIPT_TOKEN`.
3. Опублікуйте скрипт як веб-додаток (доступ: "Anyone").
4. Скопіюйте отриманий URL веб-додатка та вставте його у змінну `GOOGLE_APPS_SCRIPT_URL` у вашому файлі `.env`.

Бот автоматично створить папку `Survey_Photos` на Google Диску і буде структурувати фото по папках тем опитувань із формулами прямого перегляду у таблиці: `=HYPERLINK("view_url"; IMAGE("download_url"))`.
